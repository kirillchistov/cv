## 1. PriSMB — маркетинговый советник и прогнозатор для малого бизнеса

**Самая сильная гипотеза.** Это направление у вас разбросано по 7–8 репозиториям на разных стадиях:

| Репозиторий | Что там | Стадия |
|---|---|---|
| `next-admin-dash` | ТЗ PriSMB v1.1; маршруты advisor, import-csv, metrika, generate-creative, demo-login; демо-тур | Самый продвинутый |
| `marketingmixer` | Калькуляторы (egrocery-mix, mediamix-optimizer) на обычном JS + заготовка на Next | Прототип |
| `admin-dash` / `growcery-admin` / `nextjs-dash` | Одна и та же линия дашборда из курса Next.js Learn | Шаблоны |
| `prizma-roadmap`, `points-track-landing`, `ai-strategyst` | Лендинг unagency, лендинг Points Track, заготовка | Маркетинговая обвязка |

**Демо:** один сценарий от начала до конца. Пользователь загружает CSV из Метрики или выбирает режим «нет данных» (сценарий 6 из ТЗ). Дальше прогноз по сценариям бюджета на основе формул из `marketingmixer`. В конце AI-советник объясняет, что делать. Это прямо ведёт к задуманному продукту прогнозирования для малого и среднего бизнеса.

**Что предлагаю:**
- **Ответвление:** взять за основу `next-admin-dash` и завести ветку `demo/forecast`. Расчёты из `marketingmixer` перенести туда отдельным пакетом с чистыми функциями на TypeScript, по образцу `calculator-rates` из autobring. Тогда их можно покрыть тестами.
- **Устаревшее:**
  - `marketingmixer` подключает `next`, `react` и `recharts` с версией `"latest"` и при этом держит Vite. Так сборки невоспроизводимы. Версии лучше закрепить или уйти на стек `next-admin-dash`.
  - В `admin-dash` стоят Next 15.3, drizzle 0.32 и `@types/react@18`, хотя сам React 19. `growcery-admin` — та же панель, но уже обновлённая (Next 15.5, drizzle 0.45). Предлагаю `admin-dash` и `nextjs-dash` отправить в архив, а `growcery-admin` оставить как шаблон.
- **Стоит проверить:** последний коммит в `admin-dash` называется так же, как в `next-admin-dash` («feat(prismb): add demo tour…»), но файлов PriSMB в `admin-dash` нет. Возможно, push ушёл не в тот remote.

## 2. Call Calendar — отраслевой форк сервиса записи

**Здесь три версии одного продукта:**
- `fullstack-javascript-project-386` (sprint11) на Fastify;
- `fullstack-javascript-project-387`: тот же код плюс агентный процесс на OpenCode;
- `python-project-387`: порт бэкенда на FastAPI по тому же OpenAPI-контракту.

Функций уже много: команды, серии встреч, платные встречи через ЮKassa, уведомления в Telegram, бесплатный и платный тарифы, e2e-тесты.

**Демо:** форк под конкретную нишу, а не очередной клон Cal.com. Например, запись к репетитору с оплатой и отчётом родителю. Это стыкуется с `popmath` и `adolesson`. Другой вариант — запись на консультацию по подбору авто для autobring.

**Что предлагаю:**
- **Ответвление:** сделать основным бэкендом FastAPI. Python ближе к эконометрике, а контракт и так общий. Fastify-версию оставить как эталонную реализацию.
- **Стек:** свежий (React 19, Vite 8, React Router 7, Fastify 5), обновлять нечего. Для демо с несколькими клиентами стоит перейти с SQLite на Postgres (Supabase уже используется в `carrer-os` и `adolesson`).

## 3. AutoBring — калькулятор полной стоимости ввоза авто

**Где сейчас:** монорепозиторий на Turbo: Next, Express, Prisma. Проект остановился 1 августа на стадии демо для GitHub Pages, в веб-приложении всего 9 `.tsx`-файлов. Самая ценная часть — пакет `calculator-rates`: ставки пошлины и утильсбора с версиями и чистая функция расчёта. Это ваша профильная экспертиза.

**Демо:** вместо целого маркетплейса — встраиваемый калькулятор «под ключ» для сайтов дилеров и Telegram-каналов: страна, цена, объём двигателя, итоговая стоимость с разбивкой, и в конце заявка. Это быстрый способ получать заявки и проверить спрос на реальной аудитории.

**Стек отстаёт от ваших новых проектов:**

| Пакет | Сейчас | Предлагаю |
|---|---|---|
| Prisma | 5 | 7 |
| zod | 3 | 4 |
| zustand | 4 | 5 |
| Tailwind | 3 | 4 |
| Next | 15.0 | 16 |
| Express | 4 | Fastify 5, как в Call Calendar, или серверные экшены Next |

Ориентир — стек `carrer-os`. Одна оговорка: autobring привязан к программе курса по продвинутому React. Обновление лучше делать отдельной веткой, чтобы не разойтись с уроками.

## Что ещё заметил

- **Можно отправить в архив**, они как база для демо не нужны:
  - `react-burger`: React 18, RTK 1.9, redux-thunk. Его уже заменил `react-burger-ts`.
  - `porochute`: Lerna, yarn, Vite 4, TypeScript 4.8, Jest 28, в нём только один коммит.
  - `movies-explorer-full`: в `apps/web` стоят `react-router-dom@5` и React 18, но типы от React 19.
- **Возможная четвёртая гипотеза:** самый зрелый по стеку проект — `carrer-os` (Next 16.3, Prisma 7, Supabase, Anthropic, Playwright). Вместе с `second-project` (тренажёр собеседований по React) и `cv` из него получается «карьерный пакет».
